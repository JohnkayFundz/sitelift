Free Website Speed Test: Understand Your Results

A slow or unstable website can frustrate visitors, especially people browsing on mobile connections. A speed test helps you identify potential performance problems and decide what to investigate first. SiteLift uses Google's PageSpeed Insights service to request a Lighthouse lab audit for a public website.

Run a free website audit

Before you start

Enter a public website address and choose mobile or desktop. The report measures a test run under lab conditions. Results can vary between runs and do not guarantee real-world speed, higher search rankings, or more sales.

How to test a website

  1. Open the SiteLift audit tool.
  2. Enter the full public website address, such as https://example.com.
  3. Choose mobile first if many customers visit from phones; you can also run a desktop audit.
  4. Review the performance score, available loading metrics, and Lighthouse opportunities.
  5. Fix one or two high-impact issues, then run the test again to compare results.

What does a performance score mean?

Lighthouse converts a set of lab measurements into a score from 0 to 100. A higher score generally indicates a better result for that particular test run. Do not treat the number as a complete measure of user experience: devices, network quality, page content, and third-party services can affect how a site feels to visitors.

Metrics worth understanding

  • Largest Contentful Paint (LCP): how long it takes for the largest main content element to appear in the test.
  • Cumulative Layout Shift (CLS): how much visible page content shifts unexpectedly.
  • Total Blocking Time (TBT): how much long-running main-thread work delays responsiveness during the lab test.
  • First Contentful Paint (FCP): when the browser first renders content such as text or an image.

Common improvements to investigate

  • Resize and compress oversized images; use modern formats where supported.
  • Remove or defer JavaScript that is not needed for the first view.
  • Reduce unnecessary third-party widgets and scripts.
  • Check server response times and caching configuration.
  • Reserve space for images, ads, and embeds to reduce layout shifts.

These are starting points, not automatic instructions. Check the report details and test changes before deploying them. Avoid making changes solely to improve a score if they make the site harder to use.

Speed is only one part of a good website
